# HC-88

HC-88 is the fourth selection in **HC.rbf**. It uses the unchanged 2 KiB
bootstrap from the [HC-88 archive](https://www.z80-romania.ro/HC_88-72), verified
against MAME SHA-1 `b15a6e7085710de8b818e42d329707cb737627e3`.
It boots a disk immediately; the ROM has no BASIC/CP/M selection menu.

## Hardware

The implementation follows drawing 869.300.350 in the
[original schematics](https://www.z80-romania.ro/1989_Scheme_logice_HC_88-259),
together with the archived annotated bootstrap and revival redraw.
The three earlier HC models retain their existing firmware indices and buses.

| Resource | HC-88 behavior |
| --- | --- |
| CPU | T80pa Z80 at nominal 3.5 MHz, stopped during shared video RAM access |
| Boot ROM | 2 KiB mirrored through 0000-3FFF while LOAD_n is clear |
| System RAM | 64 KiB, with independent low-memory write protection |
| Video RAM | Separate 16 KiB, two interleaved Spectrum-layout bitmaps |
| Display | 256x192 or 512x192, per-bank ink/paper, BRIGHT and FLASH |
| Floppy | Polled 8272, two drives, motor latch, reset and terminal count |
| Keyboard/tape | Native 8x5 matrix, FE EAR input, border/beeper/MIC output |
| Serial | Original EF/F7 bit-banged signals connected to MiSTer UART pins |

The command latch is decoded by A7=1, A6=0, A0=1; software uses 9F.
Its bits are LOAD_n (0), LOCK (1), SCR (2), MOD1 (3), MOD (4) and MOD0 (5).
MOD controls only the serializer width. MOD0 removes the 4000-7FFF video overlay;
MOD1 overlays video RAM in every 16 KiB quadrant. SCR is retained but does not
create RAM on the unexpanded 16 KiB video board.

With LOAD_n set, opcode fetches at 0008-000F or 1708-170F select the automatic
low-memory shadow at system RAM 4000-7FFF. Fetches at 0700-0707 release it.
Shadow writes bypass LOCK. The BIOS uses command 31 for full 64 KiB system RAM,
and command 11 while drawing into video RAM.

| Port | Native decode and role |
| --- | --- |
| FE | A7=1, A6=1, A0=0: keyboard/EAR read, border/audio write |
| DD / DF | A7=1, A6=1, A5=0, A0=1; A1 selects 8272 status/data |
| E7 | A7=1, A4=0, A3=0: TC, drive selection, motor and controller reset |
| EF | A7=1, A4=0, A3=1: serial transmitter/handshake latch |
| F7 | A7=1, A4=1, A3=0: serial receiver and network/WAIT latch |

I/O selects remain independent, preserving overlapping address aliases.
E7 drive-select bits gate the drive motor/data path, following U95 on sheet 13.
The local-network line connects to open-drain USER bit 0, including readback
and the F7 bit-5 WAIT function. Serial transfer timing is generated by the
guest software; external UART and network inputs are synchronized.

## Replacement system disk

The [restoration discussion](https://forum.vcfed.org/index.php?threads/hc88-cp-m-bootdisk-help-please.1237701/)
and [owners' discussion](https://groups.google.com/g/romanianhomecomputer/c/GA8C14ahGzM)
identify the missing original boot disk and the different HC-91/CUB-Z BIOSes.
The forum attachments are disk directory listings, not HC-88 disk images.

`support/system.dsk` is a clearly labelled replacement. The original ROM reads
its first 512-byte sector into 8000. That sector loads CP/M and the replacement
BIOS through the ROM's own disk service and odd/even sector skew. The BIOS then
uses native 8272 commands, the keyboard matrix and an 80x24 software terminal
in 512-pixel mode. There are no CPU-level BIOS traps or host text injection.

The disk is EDSK: 80 cylinders, two heads, nine 512-byte sectors per head.
Four cylinders are reserved for the system; CP/M uses 2 KiB allocation blocks.
CCP is at D000, BDOS at D800 and BIOS at E600. Both drive slots use this DPB.

| File | Purpose |
| --- | --- |
| BASIC.COM | Loads the original HC-85 BASIC into protected system RAM and its shadow |
| DEMO.COM | Native 512-pixel colour, BRIGHT, FLASH and beeper demonstration |
| DRIVES.COM | Native drive-ready checks for both floppy slots |
| TRACK.COM | Native cylinder-79 seek/read diagnostic |
| WRITE.COM | BDOS create/write/close/reopen/read/compare diagnostic |
| README.TXT | Disk instructions and replacement identification |
| HELLO.TXT | Plain-text native floppy read sample |

CP/M CCP and BDOS come from the checksum-pinned original source in
[brouhaha/cpm22](https://github.com/brouhaha/cpm22/tree/01018abbccce0bdf4874b0b2ed1a048c5fcc2987).
The bundled [CP/M licence](licenses/cpm22.txt) applies. The new BIOS, loader and
diagnostics are in `software/`. `tools/build_hc88_disk.py` rebuilds the disk with
Pasmo. Its 8080-to-Z80 source conversion preserves the original instruction set.
The original HC-family BASIC bytes and font are unchanged.

The first three model indices remain 0=HC85, 1=HC90 and 2=HC91; HC88 is index 3.
The lossless family firmware container retains the HC88 bootstrap unchanged at
virtual offset C000. Its model index and native memory/I/O behavior are preserved;
see [shared interfaces](interfaces.md) for the container and shared storage.
